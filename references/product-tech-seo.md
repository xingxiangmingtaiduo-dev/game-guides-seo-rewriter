# Product-Tech SEO

Use this reference when the source material is about UgPhone, cloud phones, product features, tutorials, use cases, troubleshooting, or other technology topics rather than a specific game's gameplay loop.

## Core purpose

- Win Google traffic for product or technology searches.
- Explain the user problem first.
- Position UgPhone as the practical solution instead of opening with hard marketing claims.

## Common article types

Choose the closest mode before drafting:

- `feature-explainer`: explain one UgPhone feature and why it matters.
- `how-to`: teach a workflow step by step.
- `use-case`: show how a user segment solves a real problem with UgPhone.
- `troubleshooting`: answer setup, stability, login, automation, or device-limit questions.
- `comparison-without-competitors`: compare approaches or workflows without naming rival products unless approved.

## Keyword planning

- Lock one primary keyword.
- Add 2 to 5 secondary or long-tail phrases around the same user intent.
- Prefer direct high-intent phrases such as:
  - `cloud phone for [task]`
  - `how to use ugphone for [task]`
  - `remote android for [workflow]`
  - `multi-instance cloud phone`

## Title patterns

Use patterns such as:

- `[Topic] Guide (2026): [Concrete Benefit]`
- `How to Use UgPhone for [Task]`
- `[Feature] Explained: [Why It Matters]`
- `[Workflow] with UgPhone: [Outcome]`

Keep the SEO title within about 60 characters when possible and include the exact primary keyword.

## Recommended structure

Use 4 to 6 H2 sections. Pick the most suitable pattern:

### Pattern A: Feature explainer

1. `# H1`
2. Introduction
3. `## What is [Feature]?`
4. `## Key Benefits`
5. `## Common Problems` or `## FAQ`
6. `## How to Use [Feature]`
7. `## Conclusion + CTA`

### Pattern B: How-to tutorial

1. `# H1`
2. Introduction
3. `## Why [Task] Matters`
4. `## What You Need Before You Start`
5. `## How to Use UgPhone for [Task]`
6. `## Common Problems` or `## Troubleshooting`
7. `## Conclusion + CTA`

### Pattern C: Use-case article

1. `# H1`
2. Introduction
3. `## What Problem Does This Solve?`
4. `## Why Use UgPhone for [Scenario]?`
5. `## How It Works`
6. `## Common Problems` or `## FAQ`
7. `## Conclusion + CTA`

## Writing rules

- Keep one primary keyword.
- Keep the article in the `1500-1800` target band unless the user asks otherwise.
- Make the introduction and conclusion substantial.
- Explain workflow pains concretely.
- Avoid unsupported claims, competitor naming, and pricing unless approved.
- Prefer plain, useful wording over marketing-heavy adjectives.
- Revise the first draft using [human-writing-style.md](human-writing-style.md). Remove generic technology scene-setting, repeated benefit stacks, and claims that every workflow is seamless or effortless.
- Mention constraints and fit honestly. Do not imply that one setup is ideal for every user.

## Image plan

- Plan 6 to 10 images by default unless the user approves another range.
- Make every alt text describe the actual image. Use the exact primary keyword in only one or two relevant alt texts and use natural variants elsewhere.
- Prefer product screenshots, workflow diagrams, setup steps, admin views, or annotated interface captures.
