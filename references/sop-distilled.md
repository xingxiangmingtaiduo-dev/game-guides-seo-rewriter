# Game Guides SEO SOP Distilled

Use this reference when you need the detailed content rules behind the skill.

## Core purpose

- Win natural Google traffic.
- Solve a real player problem first.
- Introduce UgPhone only as the practical answer to that problem.

Keep the three-way balance:

- Make Google like the page by staying SEO-clean.
- Make players like the page by providing usable guidance.
- Make UgPhone fit naturally instead of reading like a hard ad.

## Topic taxonomy

Choose the closest article type before drafting:

- `Beginner Guide`: starter, early game, fast leveling, how to start.
- `Ultimate Guide`: complete guide, everything you need, large evergreen topics.
- `Event Guide`: seasonal or time-limited events.
- `Codes`: redeem codes, working codes, monthly code refreshes.
- `AFK Guide`: auto farm, macro, overnight farming, multi-instance play.

## Keyword planning

- Lock one primary keyword for the whole page.
- Add secondary keywords that stay close to the same user intent.
- Add long-tail phrases that mirror natural search queries.
- Avoid scattering the page across unrelated intents.

Example pattern:

- Primary: `Grow a Garden AFK`
- Secondary: `Grow a Garden Auto Farm`, `Grow a Garden Farming Guide`
- Long-tail: `How to AFK Grow a Garden Overnight`

## Title and metadata rules

- Build titles from `Game Name + hot keyword + year + concrete benefit`.
- Keep the SEO title around 60 characters when possible.
- Include the game name, main keyword, and year in the title.
- Write a lowercase slug with hyphens.
- Use 1 primary keyword plus 2 to 5 precise long-tail keywords.
- Write a meta description of about 120 to 160 characters.
- Use tags that normally include the game name plus brand terms such as `Roblox`, `Cloud Phone`, and `UgPhone Tutorial` when they fit.

## Standard article structure

Use this as the default article skeleton:

1. `# H1`
2. `Introduction`
3. `## What is [Game Name]?`
4. `## How to ...` or equivalent main guide section
5. `## Common Problems` or `## FAQ`
6. `## How UgPhone Helps` or `## Why Choose UgPhone...`
7. `## How to Use UgPhone with [Game Name]`
8. `Conclusion + CTA`

Apply these section rules:

- Make the introduction about the game and player problem, not the product.
- Let the main guide section carry most of the practical content.
- Use the UgPhone section to answer concrete constraints such as device heat, battery drain, disconnects, or multi-instance needs.
- Add a clear walkthrough for using UgPhone with the game.
- End with a clean CTA.

## Writing and formatting rules

- Target roughly `1500-1800` words unless the user wants another length.
- Keep the article scannable with H2s, bullets, numbered steps, and bold emphasis where helpful.
- Prefer useful specifics over filler.
- Avoid generic intros and weak conclusion paragraphs.
- Do not use unsupported superlatives.
- Do not mention competitors or pricing.

## Images and layout

- Prefer horizontal images.
- Use alt text that naturally includes the core keyword.
- Use clean official or self-made assets; avoid blurry screenshots or third-party logos.
- The source SOP contains an image-count conflict:
  - One section recommends `3-5` images.
  - The final checklist recommends `6-10` images.
- Default to `3-5` strong images unless the article is unusually long or the publishing team requests more density.

## Final QA checklist

- Keep one primary keyword throughout.
- Keep the H1 and SEO title aligned with that keyword.
- Use at least `4-6` clear H2 sections.
- Keep the opening and closing substantial enough to frame the guide.
- Include natural UgPhone insertion plus at least one real UgPhone how-to workflow.
- End with a clear CTA.
- Check the slug and meta description formatting.
- Check compliance: no competitor comparisons, no pricing, no broken Markdown.
